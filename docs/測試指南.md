# REGS 測試指南（Windows / PowerShell）

從零把系統跑起來並完整測過一輪 API 與判題流程。指令以 **Windows PowerShell** 為主。

> 你會用到**兩個 PowerShell 視窗**：
> - **視窗 A**：跑伺服器（`go run`，會一直卡住不還你）
> - **視窗 B**：下測試指令

---

## 0. 前置需求（每台機器只做一次）

| 需求 | 說明 |
|------|------|
| Docker Desktop | 必須**開著並顯示 Engine running**（右下角鯨魚圖示穩定） |
| Go 1.25+ | `go version` 確認（`go.mod` 要求 `go 1.25`） |
| JWT 金鑰 | `keys/private.pem`、`keys/public.pem`（見下方） |
| `.env` | 由 `.env.example` 複製，預設值本機可直接用 |

### 生成 JWT 金鑰

在專案根目錄的 **Git Bash** 執行（Windows 沒有 `make`，直接跑 openssl）：

```bash
mkdir -p keys
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out keys/private.pem
openssl pkey -in keys/private.pem -pubout -out keys/public.pem
```

> ⚠️ 重新生成金鑰後，舊 JWT 全部失效，需重新登入拿新 token。

### 建立 .env

```powershell
Copy-Item .env.example .env
```

## 1. 起資料庫

```powershell
docker compose down -v          # 清掉舊資料卷，確保 schema 重新自動初始化
docker compose up db -d         # 啟動 Postgres

# 確認五張表都建好了
docker compose exec db psql -U regs -d regs -c "\dt"
```

看到 `users / problems / testcases / submissions / submission_logs` 即成功。

> **建表是自動的**：`docker-compose.yml` 把 `internal/db/schema.sql` 掛進 Postgres 的
> `/docker-entrypoint-initdb.d/`，資料卷第一次初始化時會自動執行。只有在資料卷是空的時候才會跑，
> 所以上面先 `down -v` 清乾淨。

---

## 2. 啟動伺服器（視窗 A）

```powershell
go run ./cmd/server
```

看到 `REGS server listening on :8080` 即成功。**保持這個視窗開著**，伺服器 log 都在這裡。

---

## 3. 測 API（視窗 B）

### 3-1 註冊兩個帳號

```powershell
Invoke-RestMethod -Uri http://localhost:8080/api/users/register -Method Post -ContentType "application/json" -Body '{"username":"admin","password":"pass123"}'
Invoke-RestMethod -Uri http://localhost:8080/api/users/register -Method Post -ContentType "application/json" -Body '{"username":"alice","password":"pass123"}'
```

### 3-2 把 admin 升成管理員

`register` 建立的帳號 role 一律是 `user`，要測 Admin 端點必須手動升級：

```powershell
docker compose exec db psql -U regs -d regs -c "UPDATE users SET role='admin' WHERE username='admin';"
```

### 3-3 登入拿 token（存進變數）

```powershell
$admin = Invoke-RestMethod -Uri http://localhost:8080/api/users/login -Method Post -ContentType "application/json" -Body '{"username":"admin","password":"pass123"}'
$adminToken = $admin.token

$alice = Invoke-RestMethod -Uri http://localhost:8080/api/users/login -Method Post -ContentType "application/json" -Body '{"username":"alice","password":"pass123"}'
$aliceToken = $alice.token
```

### 3-4 JWT / RBAC 驗證

```powershell
# 需要 token 的個人資料
Invoke-RestMethod -Uri http://localhost:8080/api/users/me -Headers @{ Authorization = "Bearer $aliceToken" }

# 題目列表（Guest 可看，不用 token）
Invoke-RestMethod -Uri http://localhost:8080/api/problems
```

> 💡 `Invoke-RestMethod` 遇到 401/403 這類非 2xx 會**丟紅字例外**，那是預期行為（代表權限有擋住）。
> 想看伺服器回傳的錯誤內容，包成 `try { ... } catch { $_.ErrorDetails.Message }`。

### 3-5 建立題目（用助教的測資）

用 **admin token** 建題。`testcases` 是一組 `{input, expected}` 陣列，把助教題目的
輸入 / 標準答案填進去（JSON 內換行用 `\n`）：

```powershell
$problem = @'
{
  "title": "助教題目名稱",
  "description": "題目描述",
  "time_limit": 5,
  "testcases": [
    { "input": "測資1輸入\n", "expected": "測資1答案\n" },
    { "input": "測資2輸入\n", "expected": "測資2答案\n" }
  ]
}
'@

Invoke-RestMethod -Uri http://localhost:8080/api/problems -Method Put -Headers @{ Authorization = "Bearer $adminToken" } -ContentType "application/json" -Body $problem
```

回傳的 `id` 就是這題的 `problem_id`，下一步提交會用到（假設是 `1`）。`judge_mode` 會是 `io`。

> 若助教測資有很多組或很長，直接編輯上面的 here-string（`@' ... '@`）即可。也可以之後用同一個
> `PUT /api/problems` 帶上 `"id": 1` 來更新這題與整批替換測資。

### 3-6 建立 test-based 題目（上傳題目包，選用）

除了上面的 I/O 比對模式，系統也支援 **test-based 判題**（對應 `docs/判題模式.md`）：改用
`multipart/form-data` 上傳一個**題目包 ZIP**，內含 `CMakeLists.txt` 與 `spec/` 密測資
（例如 `test-framework/113final001`）。學生提交自己的原始碼後，系統會以題目包的 CMake 專案
配置 `-D SOURCE_ROOT=<學生原始碼>`，編譯後用 `ctest` 逐案執行。

```powershell
# 先把題目包打包成 ZIP（題目包根目錄需含 CMakeLists.txt）
Compress-Archive -Path .\test-framework\113final001\* -DestinationPath .\f001-pkg.zip -Force

# 以 admin 上傳題目包（time_limit 建議放寬，見下方說明）
curl.exe -s -X PUT http://localhost:8080/api/problems -H "Authorization: Bearer $adminToken" `
  -F "title=113final001 Complex" -F "time_limit=40" -F "file=@.\f001-pkg.zip" | ConvertFrom-Json
```

回傳的 `judge_mode` 會是 `test-based`。之後學生用同樣的 `POST /api/submissions` 提交自己的原始碼 ZIP
（把 `solution/` 或 `template/` 的 `*.cpp`、`*.h` 打包，根目錄放原始碼即可）。

> ⚠️ **關於 `Compress-Archive` 與子目錄**：Windows PowerShell 的 `Compress-Archive` 會用反斜線
> 當 ZIP 路徑分隔符（不符 ZIP 規範）。系統的解壓程式已會自動正規化，所以含 `cmake/`、`spec/`
> 等子目錄的題目包可正常判題；但若你用其他工具打包，仍建議確認 ZIP 內是正斜線路徑。

## 4. 提交專案檔測判題

前提：

- 你的 zip **解開後根目錄要有 `CMakeLists.txt`**。
- 判題會呼叫 Docker 跑 `yhlib/cs3060701`，先拉好 image：`docker pull yhlib/cs3060701`。

```powershell
# 指到要提交的 zip（助教的專案 / 你的實作）
$zip = "D:\path\to\你的專案.zip"

# 提交（檔案上傳用 curl.exe 最穩，避開 PowerShell 引號問題）
$resp = curl.exe -s -X POST http://localhost:8080/api/submissions -H "Authorization: Bearer $aliceToken" -F "problem_id=1" -F "file=@$zip" | ConvertFrom-Json
$opId = $resp.operator_id
$opId    # 印出 operator_id

# 等背景判題跑完，再查結果 + 三段 log
Start-Sleep -Seconds 8
Invoke-RestMethod -Uri "http://localhost:8080/api/submissions/$opId" -Headers @{ Authorization = "Bearer $aliceToken" }
```

回傳欄位：

| 欄位 | 意義 |
|------|------|
| `status` | 判題結果：`AC`（通過）/ `WA`（答案錯）/ `CE`（編譯錯）/ `SE`（configure 錯）/ `RE`（執行錯）/ `TLE`（逾時）|
| `configure_log` | `cmake -G Ninja -B build` 階段輸出 |
| `compile_log` | `cmake --build build` 階段輸出 |
| `output_log` | 逐測資執行與比對輸出（判錯時看這裡除錯）|

### 其他提交相關查詢

```powershell
# 個人提交列表
Invoke-RestMethod -Uri http://localhost:8080/api/submissions -Headers @{ Authorization = "Bearer $aliceToken" }

# 分段查詢單一階段 log（phase = configure | compile | output），回傳純文字
Invoke-RestMethod -Uri "http://localhost:8080/api/submissions/$opId/logs/output" -Headers @{ Authorization = "Bearer $aliceToken" }

# 重新評測（重設為 pending 並重新排入佇列；本人或 admin。改題後會載入最新定義）
Invoke-RestMethod -Uri "http://localhost:8080/api/submissions/$opId/rejudge" -Method Post -Headers @{ Authorization = "Bearer $aliceToken" }

# 下載原始 zip（本人或 admin）
curl.exe -s -OJ http://localhost:8080/api/submissions/$opId/source -H "Authorization: Bearer $aliceToken"

# 題目統計 / 使用者統計（Guest 可看）
Invoke-RestMethod -Uri http://localhost:8080/api/stats/problems/1
Invoke-RestMethod -Uri http://localhost:8080/api/stats/users/2
```

> 三段 log 也會落地為實體檔案 `storage/logs/<operatorId>/{configure,compile,output}.log`，
> 分段 API 會優先讀檔、找不到才回退資料庫副本。

> ⏱️ **判 TLE 但程式其實沒問題？** 時限是對整個 `docker run` 計時，**包含容器啟動時間**。
> 在容器啟動較慢的環境（部分 Windows Docker Desktop 主機啟動一個容器可達 10 秒以上），
> 請把題目 `time_limit` 放寬（例如 20～40 秒），否則會誤判 TLE。test-based 題目每個 case
> 各起一個容器，尤其需要放寬。

## 常見問題（這些坑都踩過）

**Q：`docker` 指令報 `open //./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified`**
A：Docker Desktop 引擎沒開。啟動 Docker Desktop、等鯨魚圖示變 running，`docker version` 要能看到 **Server** 那段。

**Q：`... < internal/db/schema.sql` 在 PowerShell 壞掉**
A：PowerShell 不支援 `<` 輸入重導向。改用自動初始化（第 1 節），或
`docker compose cp internal/db/schema.sql db:/tmp/schema.sql; docker compose exec db psql -U regs -d regs -f /tmp/schema.sql`。

**Q：`curl` 行為怪怪的 / 參數不認得**
A：PowerShell 的 `curl` 是 `Invoke-WebRequest` 的別名，不是真的 curl。要用真的 curl 請打全名 **`curl.exe`**。

**Q：伺服器啟動就報 `db: ... connection refused`**
A：`go run` 在主機上跑，需要 db 的 5432 port 有開到主機。`docker-compose.yml` 的 `db` 服務已加
`ports: - "5432:5432"`；若你的 5432 被本機其他 Postgres 佔用，改成 `"5433:5432"` 並同步改 `.env` 的
`DATABASE_URL`。

**Q：`make` 指令找不到**
A：Windows 預設沒有 `make`。Makefile 裡的指令直接手動跑即可（金鑰見第 0 節、啟動見第 2 節）。

**Q：提交後 status 一直是 `pending` / `running`**
A：判題在背景跑，看**視窗 A** 的伺服器 log。常見是 `yhlib/cs3060701` 沒 pull、或 Docker 沒開，導致
判題容器起不來。

**Q：明明程式對的卻判 `WA`**
A：輸出比對會正規化行尾空白與結尾空行，但仍需完全一致。用 `output_log` 比對 expected 與實際輸出；
另外注意判題找可執行檔是啟發式（抓 `build/` 下第一個可執行檔），複雜專案可能需調整
`internal/judge/judge.go` 的 `runScript`。
