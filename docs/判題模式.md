# Test-based 判題模式

![image](https://hackmd.io/_uploads/SkVr-dpbll.png)

本文章將會介紹 OOP 期末考試的評分模式，並說明整合進入 Online Judge 的模式，同時也會是 Online Judge 異常時的離線評分工具。

請下載[範例專案](https://github.com/silent4v/ntust-oop-test-based/archive/refs/heads/master.zip)進行操作

## 專案結構

![image](https://hackmd.io/_uploads/BJezBY6Wxl.png)


- `case.h`：由助教方公開給學生的測資
- `test.h`：進行測試的函式庫
- `entrypoint.cpp`：調用測試的主要進入點

還可能會包含其他檔案，如：文件描述、題目提供的範例檔案(例如本題會指明應該在`polynomial.h`實作題目要求)

- `online_judge`：Online Judge上進行評分的資料

>[!Caution]
>該資料夾在本專案中存在，原因是用以模擬同學在 Online Judge 上的提交(每題單獨測試)，特別針對輸出的訊息進行處理，同時告知同學 OJ 上可能會有更多測試資料
>
>正式考試中，`entrypoint.cpp` 的 `#ifdef ONLINE_JUDGE` 區塊以及 `online_judge` 資料夾是不存在於本地端的。

考量到題目可能的輸入，我們分別使用

- `TS0801` 該作業題以「替換原始碼」進行測試
- `MiddleExam006` 該題以「程式結果輸出比對」進行測試

### 程式結果輸出比對

考慮到部份題目要求同學讀取資料後，程式執行後輸出特定的格式：

```cpp
while(std::cin >> data) {
    //dosomething
    std::cout << result << std::endl;
}
```

我們會針對此情況，特別進行處理。範例 `002` 中，是原本電路輸入與量測的考題，會輸入若干指令，並且輸出特定格式的字串：

```cpp
#define INTERCEPTOR                                  \
    std::streambuf* __orig_cout = std::cout.rdbuf(); \
    std::streambuf* __orig_cin = std::cin.rdbuf();   \
    std::stringstream in{}, out{}, expected{};       \
    std::cin.rdbuf(in.rdbuf());                      \
    std::cout.rdbuf(out.rdbuf());

#define ROLLBACK                \
    std::cin.rdbuf(__orig_cin); \
    std::cout.rdbuf(__orig_cout);
```

測資會嘗試攔截 `cout` 與 `cin` 的內容，並通過一組 `std::stringstream` 模擬正式的輸入與輸出：
![image](https://hackmd.io/_uploads/ryekRqaZgx.png)

如圖所示

- `in` 模擬的是 `std::cin` 的輸入，並使用 `std::stringstream` 替換
- `expected` 是題目要求的範例輸出

分別對應到文件的 `Sample Input` 與 `Sample Output`

![image](https://hackmd.io/_uploads/rk-txj6Wxl.png)

由於 `main` 被拿去處理 OnlineJudge 的進入點，原先同學的 main ，根據題目要求需要移動到其他 `namespace`，如本範例的

```cpp
namespace OnlineJudge {
    int main() {
        // ...
    }
}
```

>[!Warning]
>由於以上操作是基於 C++ stream 的操作， scanf 與 printf 的行為可能會導致錯誤
>因此可能要請同學使用 `std::cin` 與 `std::cout` 進行 I/O，或是使用 `sprintf` 來格式字串。
>助教群提供以下範例代碼
>```cpp
>#define print_f(...) stq::print_f(__VA_ARGS__)
>
>namespace stq {
>void print_f(const char* fmt, ...) {
>    constexpr size_t BUF_SIZE = 2048;
>    char buffer[BUF_SIZE];
>
>    va_list args;
>    va_start(args, fmt);
>    std::vsnprintf(buffer, BUF_SIZE, fmt, args);
>    va_end(args);
>
>    std::cout << buffer;
>}
>}
>```
>允許同學使用 `stq::print_f` 或是 `print_f`，用`char*` 處理後，重新以 `std::cout` 輸出。但還是要請同學再次確認此操作的輸出是否有問題，或是手動使用 `sprintf` 來處理。
>
> 而讀取輸入的部份，因為通常比較制式化，同學們應該都使用 `std::cin` 進行輸入；
> 若真的有打算使用 `scanf` 或是 `gets` 進行操作，助教建議手動使用 `cin::getline` 和 `sscanf` 來處理。

## 其他功能

### 是否可以關閉預設測資？

可以，常見的情況是同學僅有部份測試失敗，比方說 Case1 的某個測資，這時請同學直接註解其他測資就好。

![image](https://hackmd.io/_uploads/BkydI5aZlx.png)

### 是否可以自定義其他測試？

可以，請在本地端的 `case.h` 中，新增一個 `TEST_CASE`，並使用 `CHECK` 新增測試。

這有助於你在檢查題目以外的行為(比方說是不是某個 Method沒有正確實作)

舉例來說，如果題目要求實作 `f()` 與 `g()`，並進行除法運算，你可以撰寫如下的測試：

```cpp
TEST_CASE("My implement") {
    // ...
    CHECK( f() == value1 );
    CHECK( g() == value2 );
    CHECK( f() / g() == value3 );
    //...
}
```

題目通常允許分割成幾個小階段驗證，你可以規劃測試後，確認自己在哪個階段失敗的。

>[!Important]
>在使用 CMake 產生 Visual Studio 工程時，CMake 會自動產生兩個輔助目標：ALL_BUILD 與 ZERO_CHECK。這些目標用於編譯流程控制，但不是你直接定義的 build target。
>| 目標           | 功能描述                              | 是否可刪除 | 備註                       |
>| ------------ | --------------------------------- | ----- | ------------------------ |
>| `ALL_BUILD`  | 建構所有可執行目標（不含 INSTALL、TEST 等）      | 否     | 等價於 `make all` 或 `ninja` |
>| `ZERO_CHECK` | 偵測 CMakeLists.txt 是否變更並自動執行 CMake | 是     | 刪除後需手動執行 `cmake` 更新      |
>
> 倘若專案無法編譯，或出現未知的錯誤，可以嘗試把 ALL_BUILD 跟 ZERO_CHECK 專案卸載
